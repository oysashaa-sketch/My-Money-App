# My Money 0.4 — Simple Money

Версия подготовлена в `feature/v0.4-simple-money` для проверки через Draft PR. Публикация и Merge не выполнялись.

## Что изменилось

- Главная показывает «Свободно сейчас»: фактический баланс минус созданные накопления и резервы платежей. Нажатие на сумму резервов открывает список. Резервирование не списывает деньги с карты. Будущая зарплата фактическим доходом не считается.
- Ниже — добавление расхода, проверка покупки, накопления, общая задолженность по кредиткам и закрытый по умолчанию блок фактических расходов по категориям с выбором месяца. Прогнозы, лимиты и распределение денег доступны в дополнительных экранах. «Свободно сейчас» не означает, что будущие обязательства и неизвестные расходы покрыты.
- Лимиты необязательны. Существующие значения сохранены; их отсутствие не мешает операциям, свободному остатку или проверке покупки. Неизвестные будущие расходы в подробном прогнозе остаются неопределёнными.
- В истории появились компактные стрелки месяцев и выбор месяца. «Расходы», накопления на цели и резервы платежей показаны отдельно. При редактировании основные поля — сумма и комментарий, остальные скрыты в раскрываемом блоке. Связи с долгами и платежами сохраняются.
- При оплате связанного платежа пользователь выбирает «Это окончательная сумма?». Подтверждение закрывает только выбранную дату даже при сумме ниже плана. Разница с планом показывается в деталях как экономия. Закрытая строка содержит только зачёркнутые название и фактическую сумму; по нажатию доступны детали и исправление закрытия.
- Старую частичную оплату можно окончательно закрыть без новой операции. Автоматически такие записи не закрываются.
- После окончательного закрытия остаток резерва освобождается без фиктивного дохода. При редактировании, удалении и повторном открытии суммы пересчитываются по сохранившимся операциям. Сверка кредитки с банком и отдельная логика Сплита сохранены.
- В резервировании главное действие — сумма и «Зарезервировать». План будущего финансирования остаётся в закрытом разделе «Дополнительно».
- Название набрано Georgia/Palatino, формы и числа — системным шрифтом. Сохранены цвета и безопасные отступы iPhone. Короткая подпись вкладки «Платежи» имеет полное доступное название «Запланированные платежи».

## Совместимость и данные

Ключ `my-money-finances-v1` и JSON `version: 1` сохранены: это прежний формат копий приложения 0.3. Загрузка не переписывает операции, ID, расписания, долги, цели и настройки. Миграция с изменением старых записей не требуется: отсутствующие новые поля трактуются как отсутствие окончательного закрытия.

Необязательные поля: `finalPayment` у операции и `paymentClosures` у состояния, с ключом `ID обязательства|дата повторения`. Повторное подтверждение не создаёт дополнительного списания. Закрытие, привязанное к операции, действует только пока эта операция существует. Экспорт и импорт сохраняют новые поля. Резервы и их освобождение вычисляются из записей, без добавления банковских приходов.

Тесты используют только искусственные примеры. Сервер для работы приложения, внешнее хранение, аналитика и платные зависимости не добавлены. Локальный HTTP-сервер ниже нужен исключительно для проверки кода в браузере.

## Ограничения

Реальный iPhone, Safari/WebKit и установленное приложение iOS в этой среде недоступны. Проверки размеров и касаний в Chromium не заменяют ручную проверку Safari. Переход обновления на iOS и системный выбор месяца следует проверить перед выпуском.

Баланс зависит от внесённых пользователем операций. Неизвестные повседневные расходы и задержки зарплаты не предсказываются. «Свободно сейчас» отражает сегодняшние резервы; для будущей покупки остаётся отдельная проверка. Проценты кредиток автоматически не вычисляются, новый остаток банка требует ручной сверки.

## Как безопасно проверить до обновления iPhone

1. Сохрани JSON из действующего приложения в частных «Файлах» iPhone. Не очищай данные Safari и не удаляй установленное приложение.
2. Скачай **код ветки** `feature/v0.4-simple-money` в отдельную папку. В ней запусти `python3 -m http.server 8081 --bind 127.0.0.1` и открой `http://127.0.0.1:8081` в отдельном профиле браузера. GitHub Pages и действующий сайт менять не требуется. Начни с вымышленных данных.
3. Проверь формулу свободного остатка, резервирование без изменения карты, окончательную оплату ниже плана и освобождение резерва. Повтори оба исторических примера через частичную оплату и отдельное подтверждение закрытия. Проверь доплату с ответом «Нет», следующее повторение, редактирование и повторное открытие.
4. Проверь свёрнутые категории, стрелки и выбор месяца, компактную историю, форму обычной покупки и банковскую сверку кредитки. Экспортируй тестовый JSON и импортируй его в другой тестовый профиль, сравни связи, суммы, статусы и резервы.
5. Для ручного теста на iPhone нужен **отдельный тестовый HTTPS-адрес**, не путь внутри действующего сайта: хранилище привязано ко всему origin (протоколу, домену и порту). Тестовый сайт этой работой не опубликован. Не импортируй тестовые копии в действующее приложение и не загружай личный JSON в репозиторий или сервис размещения кода.
6. На изолированном адресе проверь Safari и установку на домашний экран, поворот, длинные названия и суммы, нижнее меню и поля ввода. Для проверки PWA-обновления используй один тестовый адрес сначала со старым, затем с новым кодом. Дождись загрузки обновления, закрой все его вкладки и установленное тестовое приложение, открой заново и проверь данные и запуск без сети. При ожидании старой версии не очищай хранилище.

Обновлять действующий сайт следует отдельным решением после ручной проверки и свежей резервной копии. В рамках этого PR публикация не выполняется.

## Последняя UX-доработка: резервы в истории

Название записи резервирования содержит назначение связанного платежа: «Резерв: …». Для действующей части показан остаток; для использованной/освобождённой — «Использовано … · Освобождено …». Если резерв пополняли несколько раз, использование и освобождение распределяются между записями по порядку создания (FIFO), в пределах конкретной даты платежа. Одна оплата не повторяется в каждой строке. Сумма справа остаётся исходной суммой этой операции резервирования.

«Создано резервов за месяц» показывает сумму всех записей создания резервов платежей за выбранный месяц, без вычитания оплат и освобождений. Текущий остаток остаётся на главной. Это изменение представления: операции, финансовые расчёты, JSON и баланс не изменяются. Новые операции освобождения не создаются. Добавлены семь проверок активного, частично использованного и закрытого резерва, нескольких пополнений, месячного итога, повторного открытия/редактирования/удаления и старых записей. Обновлён только идентификатор кэша PWA для доставки изменённого интерфейса.
